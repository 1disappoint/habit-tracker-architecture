# Архитектура Habit Tracker (C4 Model)

**Описание системы:** Сервис для отслеживания ежедневных привычек. Пользователи могут создавать привычки и отмечать их выполнение.

## C4 Level 1 - Context
Пользователь отправляет HTTPS-запросы к системе Habit Tracker. Система сохраняет данные в PostgreSQL.

## C4 Level 2 - Container
* **API Gateway:** Входная точка, маршрутизирует запросы.
* **API Service (Java):** Основная логика приложения (Javalin).
* **PostgreSQL:** Хранение данных.
* **Redis Cache:** Кэширование для ускорения работы и снижения нагрузки на БД.

## C4 Level 3 - Component (API Service)
* **Habit Controller:** Принимает HTTP-запросы.
* **Habit Service:** Бизнес-логика.
* **Habit Repository:** Взаимодействие с PostgreSQL (SQL).
* **Redis Client:** Взаимодействие с Redis (кэширование).

## Почему выбран Redis?
Redis используется как кэш для хранения часто запрашиваемых данных (например, списка привычек). Это снижает нагрузку на PostgreSQL и ускоряет ответы API для пользователя.
